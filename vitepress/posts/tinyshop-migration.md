# 把 2020 年的商城迁到 Vue3 之后

接手 TinyShop 时的第一个问题不是「怎么写 Vue3」，而是**它根本跑不起来**。

原项目用 `node-sass@4`，这个版本只支持到 Node 12/13，在我本地的 Node 22 上装依赖就直接编译失败。也就是说，还没开始重构，我得先让它能启动。

## 先让它跑起来，再决定改哪

修构建的顺序是：删掉 node-sass 换 dart-sass → 给 webpack 4 加 `--openssl-legacy-provider` → 再跑一次 H5 构建。

能出页面之后，我才知道里面长什么样：53 个页面、47 个组件，共享状态全在 Vuex，公共逻辑塞在 mixin 里，改一个页面要同时读三处文件。

## 为什么不做逐行翻译

Vue2 选项式转 Vue3 组合式，语法上机械转换是可行的，但有两个问题：

- **没法验证**：转完之后 53 个页面里哪些还能用，只能一页页点；没有测试兜底，等于把风险转给用户。
- **结构问题没解决**：mixins 转成 composables 之后，如果还是「按页面」组织，耦合只是换了个位置。

所以我选的是另一条路：**先定分层，再迁页面**。

```
api（接口定义）
 └─ request（拦截器 / Mock 双通道）
     └─ stores（Pinia）
         └─ pages（视图）
```

每层单独能跑通之后再往上接。页面只迁「交易闭环」的 10 个，其余按业务价值排优先级。

## 分层之后顺手解决的三件事

- **请求层统一兜底**：Token 注入、401 清登录态并带 `redirect` 回跳、loading 用引用计数，避免并发请求互相关掉 loading。
- **Mock 独立成层**：按 `METHOD + url` 匹配 handler，前端不依赖后端也能走完下单；切换真接口只改一个环境变量。
- **分包有依据了**：order / account 是低频路径，放子包；主包只留首页、分类、详情、购物车。

## 结果与代价

结果是主包 629KB、H5 首屏 JS 259KB（gzip 94KB）、LCP 2.1s；

代价是**只迁了 10 / 53 页**，评价、优惠券、发票这些页面没有迁。这是明确的取舍：先保证核心链路完整可用、有测试、有 CI，剩下的按需追加，而不是为了「看起来完成了」把 53 页都糊一遍。
